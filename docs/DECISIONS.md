# Решения по ходу работы

Короткий журнал: что решено, почему, на каких данных. Даты - по Алматы.

## 2026-10-27

Стек
- Next.js 16.4 (App Router, `output: 'export'`), React 19.3, TypeScript 6.0 strict (7.0 - нативный компилятор, Next пока опирается на JS API TypeScript), Tailwind 4.3, zod 4, Vitest 5, Playwright 1.64, Lighthouse 13, pnpm 11, Node 22+.
- MDX для гайдов и страниц для покупателя - `next-mdx-remote/rsc`, frontmatter разбирается своим маленьким парсером (`lib/guides.ts`).

Шрифт
- Проверены глифы ә ғ қ ң ө ұ ү һ і (строчные и заглавные) в Google Fonts через fontTools: нет у Manrope и Unbounded; есть у Golos Text, Onest, Inter, Lora, Nunito, Rubik, Montserrat, Commissioner, Literata, PT Serif и др.
- Сначала было Golos Text + Lora (заголовки). Lora убрана ради скорости первого экрана (минус 3 файла шрифтов на мобильном). Один шрифт - Golos Text, variable, сабсеты latin/cyrillic/cyrillic-ext подключены, предзагружается только кириллица.

Данные Kaspi
- Цены, рассрочка, бонусы, наличие - из JSON листинга магазина (4 запроса), карточки и фото - со страницы товара, отзывы - API отзывов с `limit=100`. Подробности и расхождения с ТЗ - `docs/RECON.md`.
- `reviewsQuantity` у Kaspi = отзывы с текстом; все оценки = `groupSummary.ALL`. В AggregateRating: ratingCount = все оценки, reviewCount = с текстом.
- Возраст и вес для подбора: где Kaspi противоречит сам себе - берётся более осторожное значение (Tiddly и BeBorn - до 14 кг). Всё `verified: false`, бейдж на фото скрыт.
- Правила подбора (`lib/podbor-rules.ts`): максимальный вес модели не ниже верхней границы выбранного диапазона веса; минимальный возраст и вес модели - не позже середины выбранного диапазона.

Скорость (Lighthouse mobile, локальная сборка)
- Найдено и исправлено: префетч Next.js у ссылок на карточки тянул главное фото каждой карточки (160+ КБ) - на ссылках карточек `prefetch={false}`; галерея грузила все фото сразу - теперь первое, соседнее после load, остальные по листанию; миниатюры расцветок и превью YouTube - после load; CSS встроен в HTML (`experimental.inlineCss`).
- Пробовали показывать сначала лёгкое фото 370 px с подменой на чёткое - Chrome засчитывает чёткое как новый, больший LCP (6 с при реальном троттлинге). Откатили.
- Итог фазы 1: performance 91-98, accessibility/best practices/SEO 100 на главной, категории, двух карточках и гайде. LCP: при реальном троттлинге (devtools) главная/категория/гайд < 0,9 с, карточки 3,4-3,6 с; в расчётном режиме Lighthouse (simulate) 2,3-2,8 с и 3,3-3,5 с. Узкое место карточки - вес JPEG Kaspi (OPEN-QUESTIONS Р2).

Тексты
- Описания Kaspi целиком не используются (дубль и непроверенные утверждения: «одобрен ортопедами», «Oeko-Tex»). Тексты карточек - свои, на основе характеристик Kaspi, с пометкой «по карточке Kaspi» там, где значение не подтверждено Эммой.
- Генерируемые тексты («Коротко», «Что брать», сводки) проходят `checkConsistency`: вес и цены сверяются с данными, запрещены шаблонные хвосты и медицинские слова. При противоречии сборка падает.
